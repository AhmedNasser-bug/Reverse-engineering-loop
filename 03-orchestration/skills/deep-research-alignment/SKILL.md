## PHASE 1: DEEP RESEARCH PROTOCOL (IMPLICIT SINO-MENA SEARCH)

Execute `sino-mena-researcher` background pipeline and synthesize findings across 3 conceptual dimensions:

### 1. Conceptual Angles (360° View)
- **Angle A: Systemic & Structural:** Underlying architecture, data models, and core mechanics.
- **Angle B: Operational & Practical:** Real-world SLAs, benchmark metrics, cost frameworks, and production patterns.
- **Angle C: Failures & Anti-Patterns:** Known failure modes, security vulnerabilities, edge cases, and legacy traps.

### 2. Information Ingestion
- Ingest findings generated by `sino_mena_researcher.py` stored in `docs/strategy/`.
- Inspect local workspace code with targeted line-range reads (max 200 lines).

## PHASE 2: PRE-PROMPT INTERVIEW TAXONOMY

Formulate the optimal set of scoping questions categorized into 5 core pillars. Select 3-5 highest-leverage questions for the user:

### Pillar 1: Core Objective & Success Criteria
- *Question:* "What exact outcome defines 100% success for this task?"
- *Goal:* Pin down quantifiable completion metrics (e.g., latency <100ms, zero-downtime deploy, 32-slide deck).

### Pillar 2: Boundaries & Anti-Goals
- *Question:* "What MUST NOT be included or altered in this implementation?"
- *Goal:* Uncover implicit restrictions (e.g., no external CSS frameworks, preserve legacy API contracts, no dramatic headlines).

### Pillar 3: Technical & Environmental Constraints
- *Question:* "What are the exact tech stack versions, OS requirements, or hardware/API limits?"
- *Goal:* Prevent platform mismatches (e.g., Next.js 14 vs 15, Windows PowerShell syntax, Vercel deployment limits).

### Pillar 4: Audience & Output Formatting
- *Question:* "Who is the primary reader/user of this output, and what structure is expected?"
- *Goal:* Tailor design, tone, and visual layout (e.g., C-level executive summary vs raw developer documentation).

### Pillar 5: Edge Cases & Legacy Context
- *Question:* "Are there existing bugs, historical workarounds, or legacy datasets we must handle?"
- *Goal:* Avoid repeating past failures or overwriting active production configurations.
